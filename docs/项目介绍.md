# 划词问 AI

> **在网页上划一段字，用你自己的 API Key 直接问 AI。**
> 没有账号，没有中转服务器，也不绑定任何一家模型。

---

## 一、它要解决的问题

### 场景 1：读英文/技术文档时，想立刻问一句

你正在读一篇论文、一份 API 文档或一段报错日志。你想问"这段话什么意思""这个参数干什么用的"。

但你要么切到另一个标签页开 ChatGPT，把文字复制过去；要么用某款划词插件——而后者通常要求你**登录它的账号**，内容先经过它的服务器。

### 场景 2：你已经在为模型付费，不想再付第二份

你手上已经有 DeepSeek、Moonshot、智谱，或者本机跑着 Ollama 的 Key。

但市面上的划词 AI 插件是"厂商账号 + 云端模型"的形态：你要么订阅它的套餐，要么用它给的额度。**你的 Key 用不上。**

### 场景 3：你不想把正在读的东西交给看不见的第三方

网页内容里可能有公司内部文档、客户信息、未公开的代码。

多数插件会把这些内容发到它自己的服务器上，具体存哪、存多久、给谁看，你无法验证。

## 二、核心主张

这个项目只做一件事，并且把这件事的边界划清楚：

> **模型是谁的、内容去哪、代码做什么，全部由你决定并可以自己验证。**

具体体现为三条硬约束：

| 主张 | 落地方式 |
|---|---|
| **不绑定模型** | 只实现 OpenAI-compatible 协议，Base URL / 模型名 / 参数都填你自己的。DeepSeek、Moonshot、智谱、Ollama、vLLM 都能用 |
| **不经过中转** | 架构里**没有后端**：浏览器后台直接请求你配置的服务商地址。没有账号系统、没有云端历史、没有遥测 |
| **可以被审计** | 权限最小化、源码可见且可审计、关键安全约束由自动化测试和 ESLint 规则强制，而不是写在文档里 |

## 三、和豆包 / 飞书里的 AI 有什么不同

| 维度 | 豆包 / 飞书 AI | 本项目 |
|---|---|---|
| 模型 | 厂商自有 | **你自己选**，任意 OpenAI 兼容服务 |
| 付费方式 | 订阅或厂商额度 | 你的 Key，按自己的用量 |
| 数据流向 | 厂商云端（具体范围以其隐私政策为准） | 浏览器 → 你配置的服务商，**无中转** |
| 账号 | 必须登录 | **没有账号** |
| 历史记录 | 云端同步、跨设备 | 本地存储，仅此设备 |
| 生态集成 | 文档、IM、日历、企业合规 | **无**，只做网页划词问答 |
| 上手成本 | 装完即用 | 需要自己填 Key 和模型名 |
| 源码 | 闭源 | 源码可见（PolyForm Noncommercial：可读可改，禁止商用） |

**一句话区别：**
豆包卖的是"开箱即用的 AI 能力"，这个项目卖的是"**你自己掌控模型与数据的那份确定性**"。

> 说明：上表只描述"厂商账号 + 云端模型"这一公开形态。豆包具体如何处理数据，应以其隐私政策为准，本项目不做无依据的推断。

## 四、产品形态

用户在网页上选中文字后，选区下方出现一条工具栏：

```
⠿  ◆ | 问问 AI   翻译   复制
```

- **问问 AI** —— 打开侧边问答面板，自己输入问题
- **翻译** —— 打开面板并自动发起翻译
- **复制** —— 只复制文字，不发起任何模型请求

面板支持：流式输出、停止生成、复制回答、重试、连续追问，以及**拖动**到任意位置、**收起**成侧边小标签。开启"挤压式停靠"后，页面会为面板让出空间，做到完全不遮挡内容。

## 五、安全设计：不是承诺，是机制

给别人看这类项目，最该看的不是功能列表，而是**它如何防止自己变坏**。

| 威胁 | 对策 | 验证方式 |
|---|---|---|
| API Key 泄露到网页 | Key 只存在于扩展后台；UI 层**结构上拿不到明文**（响应类型里就没有这个字段） | 类型定义 + 单元测试 |
| 某个 UI 文件偷偷读 Key | ESLint 规则禁止 `background` 之外导入密钥模块，导入即报错 | `pnpm lint` |
| Key 进入 URL / 日志 / 错误文案 | 发送前自检地址不含 Key；错误只保留状态码与白名单化的错误标识，响应体原文一律不回显 | 单元测试（含"服务商回显 Key"的用例） |
| 网页脚本窃取面板内容 | 面板运行在**扩展 origin 的跨域 iframe** 中，网页脚本无法读取 | 架构隔离 |
| 内容脚本被网页指使 | 消息层做来源判定（扩展页 / 内容脚本）与类型白名单；内容脚本**只能提交一段受限文本**，碰不到配置与 Key | 单元测试 |
| 模型输出里的 XSS | Markdown 渲染采用**解析后重建**的白名单方式：禁止原始 HTML、禁止图片与外部资源、链接只允许 http/https/mailto | 10+ 个 XSS 向量用例 |
| 权限过大 | 只申请 `storage` / `scripting` / `activeTab`，**没有任何 host_permissions**；划词脚本按需注入，不常驻所有页面 | 构建产物 manifest 核对 |
| 网页文字当作指令执行 | 系统提示中明确声明"引用文字是不可信数据"；历史消息只接受 user/assistant，禁止客户端注入 system | 单元测试 |

同时明确说明**边界**：浏览器本身、恶意扩展、被篡改的扩展代码，或拥有本机扩展执行权限的攻击者，仍可能接触到凭证。**本项目不宣称"API Key 绝对安全"。**

## 六、工程数据

| 指标 | 结果 |
|---|---|
| 单元测试 | **14 个测试文件 / 195 个用例，全部通过** |
| TypeScript | `strict` + `noUncheckedIndexedAccess`，`tsc --noEmit` 0 错误 |
| ESLint | 0 error / 0 warning |
| 构建 | Chrome / Edge 与 Firefox 均通过 |
| 权限 | `storage`、`scripting`、`activeTab`，无 host_permissions |

几处值得一提的实现细节：

- **流式输出不依赖响应头**。很多兼容服务把 SSE 响应的 `Content-Type` 标成 `application/json`，若按响应头分流就会退化成"等全部算完再显示"。这里改为按响应体实际形态判断（SSE / 逐行 JSON / 纯文本），三种都边收边吐。
- **SSE 解析独立成纯类**，网络分片在任意字节位置被切断都能正确重组。
- **Markdown 消毒自研白名单重建**：曾用 DOMPurify，但在本项目构建链中出现"配置与行为不一致"的不确定表现，安全清洗不应依赖行为不确定的组件，故改为解析后重建节点树，原始节点从不插入文档。
- **错误统一归一化**：区分超时 / 用户取消 / 网络错误 / 断流不完整，避免把"用户点了停止"误报成"超时"。

## 八、适合谁 / 不适合谁

**适合**

- 已经有模型 API Key、希望直接复用的开发者与技术用户
- 对"内容被上传到哪"敏感、愿意花两分钟配置的人
- 想读一份小而可审计的扩展代码的人

**不适合**

- 想要装完即用、不想申请 Key 的普通用户 → 用豆包这类产品更合适
- 需要跨设备同步历史、需要团队协作与合规背书的人
- 企业环境（大概率不允许自行安装扩展）

## 九、快速试用

```bash
git clone https://github.com/abayern/ASK-AI-browser-plugin.git
cd ASK-AI-browser-plugin
pnpm install
pnpm build:chrome
```

1. 打开 `chrome://extensions`，开启开发者模式
2. 「加载已解压的扩展程序」，选择 `.output/chrome-mv3`
3. 点工具栏图标 → **打开设置** → 填写服务商、Base URL、模型名、API Key
4. 回到任意网页，点图标 → **在本页启用划词**
5. 选中一段文字 → 点「问问 AI」

> Firefox：`about:debugging` → 临时载入 `.output/firefox-mv3/manifest.json`

## 十、已知限制

- 每个页面需要点一次「在本页启用」（权限持久化尚未实现）
- 历史会话与长期记忆尚未开发
- 少数网站因 CSP 限制可能无法嵌入面板
- 挤压式停靠会改动页面布局，个别站点（固定定位导航、全宽画布）可能错位，可随时关闭
- 尚未在真实浏览器中完成三端完整手测
